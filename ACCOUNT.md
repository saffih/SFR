# SFR account and workspace profile

This optional **host-agnostic opt-in** applies SFR to ordinary work in the scope where it is actually installed. It is not a second SFR runtime, automatic background monitor, or a substitute for a host's installation mechanism.

## Account behavior

1. **Use SFR for work within the installed scope**, including ordinary follow-ups. A saved instruction selecting this profile is an affirmative SFR invocation; merely mentioning SFR elsewhere is not. Keep trivial work unobtrusive. A new unrelated objective forms a new Root; do not invent continuity from topic similarity. Explicit user opt-outs take precedence for their stated scope.
2. **Bind the source at workstream start and real handoff.** Load the authorized current [SFR runtime](sfr.md); it alone governs Root/DONE, the single active Frame, current focus, bounded Child return, route, and Close. Where the host deliberately binds a different source, name and verify it instead of silently substituting public content. If inaccessible, disclose `SOURCE_UNAVAILABLE` and do not claim SFR compliance.
3. **Keep SFR human-visible when work is substantial.** Prefer a concise recognizable opening Root/Frame-path/focus/next-action orientation, followed by meaningful work-and-reason updates and material Frame/focus changes. Do not repeat information already communicated by the host, or add per-tool narration; keep trivial work unobtrusive.
4. **Observe material behavior.** This profile selects optional [OBSERVE.md](OBSERVE.md). At real activation, important focus/Child/return transitions, handoff preparation and receiving, and Root Close, inspect observable correctness and the human-visible communication when that event is sampled. Do not checkpoint every answer.
5. **Track when permitted.** Use the user's separately configured, accessible **private** tracking store, if any. Record only actual sampled events with source and evidence; read back each write before claiming persistence. Use `OBSERVED_PASS`, `OBSERVED_FAIL`, `UNVERIFIED` and `NOT_APPLICABLE`. Missing records, inaccessible receivers, self-reports and simulations are not proof of independent handoff correctness. If tracking is unavailable, continue the user's work and disclose only material limitations.
6. **Prepare real same-workstream handoffs under the runtime:** explicit receiver SFR activation, Root/DONE, active Frame/return links, valid focus/first justified action, established completions, blockers and source references. The receiver must revalidate the current frontier and take its own justified first action. A sender prompt alone cannot establish receiver success. Do not leak private tracker references or local configuration to public or unrelated receiving contexts.
7. **Report only what the host proves.** Saved memory, agent files, custom instructions, or one successful chat do not establish that every future conversation inherited the binding, that other chats were monitored, or that any tool write succeeded.

## Install or rebind

Follow [INSTALL-BINDINGS.md](INSTALL-BINDINGS.md) to choose a real persistent mechanism for each environment: user instructions, project/workspace instructions, agent file, explicitly writable memory or an equivalent supported mechanism. Do not duplicate SFR's rules into the binding. Private source and tracker addresses must live outside this public profile.

**Operating principle:** preserve attention through SFR, sample meaningful correctness, persist only verified evidence when allowed, and return to the actual task.
